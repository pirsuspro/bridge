================================================================================
            Z.AI BRIDGE v2.3 — УСТАНОВОЧНЫЙ ПАКЕТ (чистый шаблон)
================================================================================
Пакет для развёртывания такого же моста на другом компьютере и в другой
песочнице Z.ai. Все личные данные (адреса, токены, имена ПК, пути)
удалены — это чистый шаблон.

Версия: сервер Bridge API 1.0.0 (feats: binchunk, gzip),
        агент bridge.ps1 v2.3.0.


ЧТО ЭТО ТАКОЕ
-------------

Мост между песочницей Z.ai (облачная среда, в которой работает ваш
ИИ-ассистент Z.ai Code) и вашим ПК на Windows. После установки:

  - ИИ видит файлы в выбранной вами папке на ПК (список, чтение, запись,
    переименование, удаление);
  - ИИ может запускать на ПК команды (cmd.exe) и фоновые процессы,
    читать их вывод в реальном времени и писать в их stdin;
  - двусторонняя передача файлов (до 2 ГБ, чанками по 1 МБ, контроль
    SHA256); в v2.3 чанки идут сырыми байтами с gzip-сжатием — это
    быстрее base64 в 1.5-2 раза на тексте и коде;
  - чат «пользователь <-> ИИ» прямо на странице моста: сообщения
    попадают в очередь, ИИ отвечает через API (автономный режим);
  - всё через обычный исходящий HTTPS: мост сам инициирует соединение
    из вашего ПК, открывать порты и настраивать роутер не нужно.

Схема работы:

    [Песочница Z.ai]                [Ваш ПК с Windows]
    Next.js-сервер (порт 3000)      bridge.ps1 (PowerShell-агент)
    SQLite (Prisma) — очередь           |       \
    команд, передачи, чат               |        +-- папка моста
         ^   HTTPS (poll / result /     |             (напр. C:\zai-share)
         |   chunk / done / chat...)    |
         +------------------------------+
              агент сам опрашивает сервер каждую секунду

Агент каждые ~1 секунду спрашивает сервер «есть команды?», получает их из
очереди, выполняет (файловые операции, запуск процессов, передачи файлов)
и отправляет результат обратно. Страница «Мост» в Preview-панели —
дашборд: статус, файловый менеджер, чат, терминал, процессы, передачи,
журнал работы ИИ.

ЧТО НОВОГО В v2.3 (сверх v2.2.1)
--------------------------------
  Скорость (уроки десктопного SSH-клиента motty):
   - чанки ПК<->песочница — сырые байты (application/octet-stream)
     вместо base64-in-JSON (минус 25-33% трафика, без конвертации
     мегабайтных JSON на каждом чанке);
   - gzip чанков в обе стороны, когда выгодно (текст/код — в 3-5 раз
     меньше); сервер объявляет возможности в ответе poll: feats:
     ["binchunk","gzip"]; старый сервер без feats — агент сам откатится
     на base64-JSON (обратная совместимость);
   - Expect100Continue/Nagle выключены, ConnectionLimit 8 — отклик
     poll/чанков без лишних задержек.
  Новые возможности сервера:
   - чат (BridgeChatMessage): пользователь пишет на странице моста,
     ИИ забирает сообщения через GET /chat/pending и отвечает через
     POST /chat/agent;
   - GET /journal — хвост journal/JOURNAL.md (журнал прогресса ИИ);
   - GET /memory — база знаний ИИ (agent-memory/*.md, только чтение);
   - ретенция: готовые команды/передачи старше 24 ч удаляются раз в
     час (SQLite больше не раздувается до сотен МБ).


ТРЕБОВАНИЯ
----------

  1. Аккаунт Z.ai с доступом к Z.ai Code (веб-проекты).
  2. Стандартная песочница Z.ai Code: Next.js 16 + TypeScript + Prisma +
     shadcn/ui + framer-motion + lucide-react. Всё это создаётся/стоит
     в песочнице автоматически — ДОПОЛНИТЕЛЬНО НИЧЕГО СТАВИТЬ НЕ НАДО.
     (Нужны shadcn-компоненты: alert, badge, button, card, checkbox,
     collapsible, dialog, dropdown-menu, input, label, progress, select,
     skeleton, switch, tabs, textarea, toaster + хук use-toast —
     в стандартной песочнице уже есть.)
  3. ПК на Windows 10/11 (PowerShell 5.1 встроен; pwsh 7 тоже подходит).
  4. Интернет на ПК (исходящий HTTPS, порт 443).

ШАГ 1. СЕРВЕРНАЯ ЧАСТЬ В ПЕСОЧНИЦЕ (собирает ваш ИИ-ассистент, ~5 минут)
------------------------------------------------------------------------

1. Начните в Z.ai новый веб-проект — создастся песочница со стандартным
   Next.js-проектом.

2. Передайте ИИ исходники моста любым способом:
   - РЕКОМЕНДУЕТСЯ: прикрепите к сообщению в чат один файл
     bundle_for_agent.txt (в нём все файлы с маркерами путей);
   - или прикрепите всю папку bridge_install / архив с ней;
   - или файлы из папки sandbox\ по одному.

3. Отправьте ИИ запрос. Готовый текст для копирования:

   ---------------------------------------------------------------------
   Собери, пожалуйста, мост Z.ai Bridge версии v2.3 из прикреплённого
   пакета. Это проверенный рабочий набор файлов, ничего не изобретай
   заново — просто воссоздай файлы. Порядок:

   1) Если в пакете есть sandbox/deploy.sh — можно запустить его из
      корня проекта: bash bridge_install/sandbox/deploy.sh — он сам
      разложит все файлы и допишет модели Prisma. ИЛИ разложи вручную:
      структура папок в пакете повторяет структуру проекта;
      содержимое бери из txt-файлов, расширение .txt отбрасывай
      (файл «bridge.ts.txt» -> src/lib/bridge.ts).
      Файл prisma/schema.bridge.models.prisma.txt — это НЕ весь schema,
      а фрагмент: добавь его содержимое В КОНЕЦ существующего
      prisma/schema.prisma (4 модели: BridgeCommand, BridgeTransfer,
      BridgeSetting, BridgeChatMessage).

   2) ОБЯЗАТЕЛЬНО положи bridge.ps1 и installer.template.bat в папку
      bridge-client/ в корне проекта — их раздаёт API установщика
      (GET /api/bridge/setup/ps1 и /setup/installer).

   3) Замени src/app/page.tsx и src/app/layout.tsx на версии из пакета.
      Если src/lib/db.ts уже существует — не трогай его.

   4) Выполни: bun run db:push

   5) Перезапусти dev-сервер. Проверь:
      - страница «Мост» открывается в Preview-панели;
      - curl -s http://localhost:3000/api/bridge/status
        отвечает {"ok":true,"token":"...","online":false,...}

   После этого напиши мне, что серверная часть готова, и напомни
   открыть Preview-панель и скачать установщик.

   Карта файлов (49 файлов проекта):
     bridge-client/bridge.ps1.txt              -> bridge-client/bridge.ps1
     bridge-client/installer.template.bat.txt  -> bridge-client/installer.template.bat
     prisma/schema.bridge.models.prisma.txt    -> prisma/schema.prisma (добавить 4 модели в конец)
     src/lib/bridge.ts.txt                     -> src/lib/bridge.ts
     src/lib/db.ts.txt                         -> src/lib/db.ts (если уже есть — не трогать)
     src/app/layout.tsx.txt                    -> src/app/layout.tsx
     src/app/page.tsx.txt                      -> src/app/page.tsx
     src/components/bridge/<файл>.txt          -> src/components/bridge/<файл>  (14 шт.)
     src/app/api/bridge/<путь>/route.ts.txt    -> src/app/api/bridge/<путь>/route.ts (28 шт.)
   ---------------------------------------------------------------------
4. Проверка шага: в Preview-панели откройте приложение. Вы должны увидеть
   тёмную страницу «Z.ai Bridge» с карточками «Подключение», «Файлы»,
   «Чат», «Терминал». Статус агента — «Офлайн»/«Не подключён»: это
   нормально, ПК ещё не подключали.

   Примечание: если при сборке ИИ сообщает, что каких-то компонентов
   shadcn/ui не хватает, попросите его доустановить их стандартной
   командой shadcn — в обычной песочнице они уже есть.

ШАГ 2. ПОДКЛЮЧЕНИЕ ВАШЕГО ПК (~2 минуты)
----------------------------------------

1. На странице «Мост» в Preview-панели найдите карточку «Подключение» и
   нажмите «Скачать установщик (.bat)». Скачается zai-bridge-setup.bat,
   в который уже вшиты адрес ВАШЕЙ песочницы и ваш токен.

2. Создайте на ПК отдельную папку (например, C:\zai-bridge), положите
   туда установщик и запустите двойным кликом.
   - SmartScreen может предупредить о неизвестном издателе:
     «Подробнее» -> «Выполнить в любом случае» (это ваш собственный
     скрипт, просто без цифровой подписи).
   - Установщик скачает bridge.ps1 с сервера и запустит его.

3. При первом запуске мост спросит путь к папке на ПК, доступ к которой
   вы даёте песочнице.
   ВАЖНО: выделяйте отдельную папку-песочницу (например C:\zai-share),
   а не весь диск или профиль — ИИ получит к ней полный доступ.

4. Дождитесь статуса «Онлайн» вверху страницы «Мост» (обновляется
   каждые 5 секунд).

Готово. Окно моста держите открытым, пока нужен доступ. Установщик
работает как watchdog: если агент упадёт — перезапустит его через 3
секунды. Полная остановка — закрыть окно консоли.

Альтернатива без установщика (ручной режим):
   - скачайте со страницы «Мост» файл bridge.ps1 (кнопка «Скачать
     bridge.ps1») и положите в C:\zai-bridge;
   - запустите: powershell -NoProfile -ExecutionPolicy Bypass -File
     bridge.ps1 -Url https://АДРЕС-ПЕСОЧНИЦЫ -Token ТОКЕН
     (адрес и токен — на странице «Мост»);
   - при первом запуске спросит папку и сохранит всё в bridge_config.json;
   - для автоперезапуска используйте start-bridge.example.bat из этого
     пакета (переименуйте в start-bridge.bat и положите рядом).


КАК ПОЛЬЗОВАТЬСЯ
----------------

Дальше просто общайтесь с ИИ в чате как обычно — он теперь умеет сам
работать с вашей папкой. Примеры запросов:

  «Покажи, что лежит в папке моста»
  «Собери проект из папки моста и покажи ошибки компиляции»
  «Возьми файл report.txt из папки моста и разбери его»
  «Запусти game.exe в фоне и следи за выводом, покажи лог когда упадёт»
  «Скопируй результаты тестов из папки моста к себе»

На странице «Мост» доступны:
  - Подключение: токен, скачивание установщика, смена токена;
  - Файлы: браузер по папке моста на ПК (загрузка/скачивание/удаление);
  - Чат: сообщения агенту (ИИ заберёт их через /chat/pending и ответит);
  - Терминал: команды на ПК (синхронно с таймаутом или в фоне),
    список фоновых процессов, запись в их stdin, остановка;
  - Передачи: журнал передач файлов с прогрессом и SHA256;
  - Журнал: последние команды + журнал прогресса ИИ (journal/JOURNAL.md).

Ограничения моста (встроены в код):
  - всё строго внутри выбранной папки (защита от выхода по «..» и
    абсолютным путям);
  - стоп-лист команд: format, shutdown, diskpart, mkfs, bcdedit,
    vssadmin delete;
  - команды до 10 000 символов, таймаут синхронного exec до 600 с;
  - текстовые файлы до 2 МБ через быстрые read/write, большие —
    через передачи с чанками;
  - передача «зависает» (failed), если нет прогресса 5 минут;
  - команда без ответа агента 90 с -> failed (sweeper);
  - готовые команды/передачи старше 24 ч удаляются (ретенция).


БЕЗОПАСНОСТЬ
------------

  - Токен моста = ключ к папке на вашем ПК. Не показывайте и не
    передавайте его.
  - Ссылка на Preview-панель вашего чата = доступ к мосту (там же
    виден токен). Не передавайте её третьим лицам.
  - Если токен утёк: на странице «Мост» нажмите «Повернуть токен»,
    скачайте установщик заново и перезапустите мост на ПК. Старый
    токен мгновенно перестанет работать.
  - Мост не запускается от администратора и не требует прав —
    обычного пользователя достаточно.


ЧАСТЫЕ ПРОБЛЕМЫ
---------------

  «Агент не подключён» / статус «Офлайн»
      Окно моста на ПК закрыто или упало. Запустите zai-bridge-setup.bat
      снова (или start-bridge.bat в ручном режиме).

  Установщик не может скачать bridge.ps1
      Проверьте: интернет на ПК работает; песочница запущена и страница
      «Мост» открывается в Preview-панели. Установщик качает файл с
      /api/bridge/setup/ps1 — если роут вернул ошибку, серверная часть
      собрана не полностью (см. ШАГ 1).

  «Другой экземпляр моста уже запущен»
      Мост уже работает в другом окне (защита через глобальный mutex).
      Закройте старое окно и запустите снова.

  409 при перезапуске моста — это нормально в первые ~25 секунд:
      сервер считает старый процесс ещё «онлайн». Агент сам ждёт и
      переподключается.

  Кириллица в выводе команд — «кракозябры»
      Агент применяет эвристику UTF-8/CP866 построчно. Если конкретная
      утилита печатает мусор, запускайте её с «chcp 65001 >nul & ...».

  Пересобрали песочницу / новый чат — адрес изменился
      Адрес песочницы уникален для каждого чата. Скачайте установщик
      заново из нового чата и перезапустите мост. Старый установщик
      больше не подключится (это защита).

  Мост «завис» намертво
      В агенте есть внутренний watchdog: если основной цикл не подаёт
      признаков жизни 10 минут, процесс убивает себя, а bat-лаунчер
      перезапускает его. Можно просто перезапустить вручную.

  Передачи стали медленными после обновления сервера
      Убедитесь, что агент свежий (v2.3.0: в ответе poll есть
      "feats":["binchunk","gzip"]). Старый агент продолжит работать
      через base64 — это медленнее, но совместимо.


ТЕХНИЧЕСКИЕ ДЕТАЛИ (для интересующихся)
---------------------------------------

  API-маршруты (все под /api/bridge):
    GET  /status                     статус + токен (для UI)
    POST /poll                       агент: получить команды (long poll);
                                   в ответе feats: [binchunk, gzip]
    POST /result                     агент: результат команды
    POST /exec                       агент: вывод синхронного exec
    POST /proc                       агент: операции с фон. процессами
    POST /text                       read/write текстовых файлов на ПК
    POST /action                     ping/stat/list/mkdir/delete/move
    POST /pull                       затянуть файл с ПК в песочницу
    POST /push                       отправить staged-файл на ПК
    PUT  /file/<name>                загрузить файл в staging песочницы
    GET  /files                      список staged-файлов
    GET  /transfers                  список передач
    POST /transfer/<id>/chunk        чанк передачи (bin или base64, gzip)
    POST /transfer/<id>/complete     ПК->песочница: файл собран
    POST /transfer/<id>/done         песочница->ПК: файл получен
    POST /transfer/<id>/fail         пометить передачу сломанной
    GET  /command/<id>               статус конкретной команды
    GET  /log                        журнал команд
    POST /rotate                     смена токена
    POST /agent/restart              попросить агента перезапуститься
    GET  /setup/ps1                  скачать bridge.ps1 (с BOM и CRLF)
    GET  /setup/installer?origin=... сгенерировать zai-bridge-setup.bat
    GET  /chat                       история чата (пользователь <-> ИИ)
    POST /chat                       сообщение пользователя агенту (UI)
    GET  /chat/pending               необработанные сообщения (для ИИ)
    POST /chat/agent                 ответ ИИ в чат
    GET  /journal                    журнал прогресса ИИ (journal/JOURNAL.md)
    GET  /memory                     база знаний ИИ (agent-memory/*.md)

  Модели Prisma (SQLite): BridgeCommand (очередь команд), BridgeTransfer
  (передачи), BridgeSetting (token/lastSeenAt/clientId/clientInfo),
  BridgeChatMessage (чат). Токен генерируется при первом запросе
  /status и живёт в БД — в коде токенов нет.

  Безопасность транспорта: постоянное сравнение токена
  (crypto.timingSafeEqual), токен передаётся в заголовке x-bridge-token
  или параметре ?t=. SQLite хранит очередь — ничего не теряется при
  рестарте сервера в рамках сессии.

  Агент bridge.ps1: один экземпляр на машину (глобальный mutex),
  постоянный clientId (переживает рестарты), ротация лога на 5 МБ,
  C#-движок процессов с Latin-1 транспортом и пост-декодированием
  (UTF-8 строгий, иначе CP866 построчно), watchdog от зависаний,
  автосжатие чанков gzip + бинарный транспорт при feats на сервере.

  Обслуживание БД: sweeper помечает зависшие команды/передачи
  (90 с / 5 мин без ответа); ретенция раз в час удаляет завершённые
  записи старше 24 ч и осиротевшие staged-файлы.

Пакет самодостаточен и проверен в работе (Next.js 16 App Router,
